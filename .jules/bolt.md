## 2024-03-24 - [Avoid Regex Recompilation in Text Utilities]
**Learning:** High-frequency utility functions like `clean_text` are called repeatedly for every processed email. Using `re.sub` with string patterns inline causes the regex engine either compile the pattern on the fly or rely on its small internal cache. When multiple patterns are used across many calls, this introduces unnecessary overhead.
**Action:** Pre-compiled regular expressions at the module level using `re.compile()` and utilized the `.sub()` method on the compiled objects. Next time I encounter high-frequency string processing, I should always check if regex patterns can be compiled once at initialization or module level.
## 2024-05-24 - [Avoid Regex Recompilation in NLP Data Strategy]
**Learning:** High-frequency processing functions like `_clean_email_content` and `_extract_features` within `src/backend/python_nlp/data_strategy.py` process thousands of samples during dataset creation. Calling `re.sub()`, `re.search()`, and `re.findall()` with string patterns inside loops forces the regex engine to either compile on the fly or rely on its small internal cache. Pre-compiling patterns in `__init__` and utilizing `.sub()`, `.search()`, and `.findall()` on compiled objects speeds up batch processing.
**Action:** Always verify if heavily-used string manipulation or feature extraction loops can leverage `re.compile()` stored at the class level or module level, avoiding redundant compilations in hot paths.
